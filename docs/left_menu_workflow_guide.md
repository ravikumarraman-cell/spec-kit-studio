# Studio navigation guide

The sidebar presents the available workspace surfaces. Labels and visibility can depend on the active workflow, so it is not a linear automation pipeline.

| Surface | Current purpose |
| --- | --- |
| Overview | Shows the active workspace, delivery status, and next workflow action. |
| Connected Workspace | Pairs with the optional connector, scans repository evidence, manages Spec-Kit setup, and records a baseline. |
| Feature Spec | Edits user stories, requirements, edge cases, and related specification data. |
| Architecture Plan | Edits technology choices, ADRs, API contracts, data schemas, and architecture notes. |
| Task Board | Reviews and tracks delivery tasks and mappings. |
| Constitution | Records project rules and constraints. |
| AI Agent Prompts | Builds task-scoped prompts and presents local-agent execution and receipts when the connector is configured. |
| Audit | Shows deterministic traceability checks and, when configured, AI-assisted audit output. |
| Exporter | Previews/downloads workspace or delivery packages and supports reviewed connector writes. |
| Workflows | Hosts the independent Bug Fix and Idea Assessment flows when one is active. |

The Feature Journey is the primary guided path for delivery work. It adds explicit review gates around connection, scope, impact, design, tasks, audit, implementation, and handoff.

No screen can guarantee that an agent will not make a mistake or that a specification is complete. Use repository evidence, review, and relevant verification to make those judgments.
